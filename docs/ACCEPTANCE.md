# Ручная приёмка Windows и Tilda

Этот протокол ещё не выполнен. Локальный pytest подтверждает обработку данных, а не принятие файлов Tilda.

## Windows 10/11 x64

1. Выполнить `Build Windows.cmd` на Windows с Python 3.12. Сохранить `build-test-results.xml`; все GUI-тесты должны выполняться без ST_SKIP_QT.
2. Распаковать полученный ZIP на Windows-компьютере без Python. Запустить EXE. Проверить 5 каталогов, 556 записей и поиск «ДипИФР».
3. Проверить окно при масштабировании 100%, 125%, 150% и разрешении 1366×768: надписи читаются, кнопки доступны, таблицы прокручиваются.
4. Проверить недоступность «Продолжить» до флажка риска; после перезапуска флажок не должен оставаться подтверждённым.
5. Изменить одну группу/цену, закрыть EXE и открыть снова. Сверить значения и UID.
6. Проверить добавление/копирование группы, отдельную правку HTML-фрагмента и сохранение без правок. При переключении HTML-режимов проверить теги, атрибуты, неразрывные пробелы и Unicode.
7. Выбрать один, три и пять сайтов в региональном редакторе. Проверить цену/часовой пояс каждого региона; два невыбранных сайта должны остаться прежними.
8. Перетащить 5 CSV, выбрать полные/частичные. Проверить конфликт цены и оба решения. Отмена диалога не должна решать конфликт.
9. Проверить архив экспорта, отдельные имена доменов и инструкцию удаления. Подтверждение старого экспорта не должно менять статус поздней правки.
10. Создать резервную копию, изменить данные, восстановить. Перенести копию на второй компьютер. Проверить данные, историю, соответствия.
11. Попытаться открыть два экземпляра с одной базой — второй должен отказать. Проверить старт после аварийного завершения (Qt удаляет устаревшую блокировку завершившегося процесса).

## Tilda — только копия проекта на первом испытании

1. Сделать полную резервную выгрузку исходного каталога. Создать тестовую копию каталога/проекта без боевого трафика.
2. Загрузить её актуальный CSV в отдельную базу приложения через `--data-dir`; подтвердить правильный сайт при необходимости.
3. Изменить цену и расписание существующего варианта ДипИФР и добавить одну новую группу. Сохранить его UID и UID новой строки для проверки.
4. Экспортировать изменения. Сопоставить Tilda UID, Parent UID, Editions, Modifications и Tabs. Не игнорировать UID, не очищать каталог, не использовать совпадение названия для группировки.
5. Проверить, что существующая запись обновилась без дубликата; новая появилась под правильным родителем; дополнительные опции и вкладки не потерялись; другие варианты сохранены.
6. Сравнить HTML, SEO, фото, категории, цены и количество с исходной выгрузкой. Проверить `::`, Unicode `դր.`, валютные символы и переносы строк.
7. Повторно импортировать тот же CSV. Новая группа не должна дублироваться.
8. Сделать свежую полную выгрузку из Tilda и загрузить в приложение. Проверить статус совпавших значений. Нормализации самой Tilda должны появляться как реальные отличия, а не молча скрываться.
9. Отдельно испытать полный экспорт. Убедиться, что другие записи не изменены.
10. Пометить группу для удаления, сформировать инструкцию, удалить вручную в Tilda, подтвердить в приложении, загрузить полную выгрузку. Запись должна скрыться из активного списка, оставаясь в истории.
11. Повторить контрольные операции на каждом из пяти регионов, особенно международные Tabs и армянские аномалии.

Не считать созданный CSV или ручную отметку «импорт подтверждён» доказательством прохождения этого протокола.
