# Архитектура

## Компоненты

- `domain.py`: модель Product, точный разбор названий свойств, расписание, предложения сопоставлений, HTML-текстовые фрагменты. Нет Qt/SQLite.
- `csv_io.py`: стандартный csv, UTF-8, разделитель `;`, контроль ширины записей/заголовков, определение сайта, дата файла.
- `repository.py`: SQLite, схема, чтение/запись моделей, журнал, транзакции SAVEPOINT, backup API, восстановление. Единственное место соединения с SQLite.
- `service.py`: сценарии импорта, трёхстороннее сравнение, редактирование, группы, сопоставления, удаление и экспорт. Не зависит от Qt. Часть операций журнала/конфликтов выполняется через соединение репозитория; при переходе на сервер потребуется вынести эти SQL-операции за адаптер, а не переписывать правила CSV/расписания/валидации.
- `validation.py`: чистые проверки текущего набора строк и сравнение с исходными дефектами. Проверки ничего не исправляют.
- `ui.py`: русскоязычные Qt-виджеты, формы, подтверждения, предварительный просмотр. Бизнес-сценарии вызываются через сервис.
- `__main__.py`: пользовательская папка, блокировка второго экземпляра, старт, автоматическая резервная копия, smoke-test.

## Таблицы SQLite

| Таблица | Назначение |
|---|---|
| catalogs | ID/регион/домен, упорядоченные заголовки, даты |
| products | Внутренний ключ, сайт/порядок, original/base/current, флаги новой/удалённой/отсутствующей записи |
| history | Дата UTC, сайт, запись, поле, старое/новое, статус |
| imports | Имя/дата/полнота, полный снимок пришедшего файла |
| conflicts | Три значения поля, состояние разрешения |
| exports | Путь, режим, снимок точных строк, состояние и максимальный ID журнала |
| mappings | Подтверждённая группа соответствий: один основной товар на сайт |

Товар и вариант — одна модель строки; различие задаёт Parent UID. Modifications сохраняется как отдельное поле строки, не смешивается с дочерними вариантами. Неизвестные поля входят в JSON и сохраняются. Исходники в пакете защищены SHA-256 при начальном заполнении. `initial-catalog.sqlite3` — дополнительная резервная поставка, автоматически поверх рабочей базы не копируется.

## Гарантии и границы

- Любая локальная операция записывает только явно изменённые поля. Идентификаторы существующей записи защищены.
- Расписание использует точное название свойства родителя, включая завершающее двоеточие; часы с двоеточиями не разделяются.
- Экспорт сначала валидирует выбранные сайты, пишет временную папку, повторно читает и сравнивает ячейки, публикует новую папку и фиксирует журнал.
- Между SQLite и файловой системой нет общей распределённой транзакции. При аварийном завершении процесса/отключении питания в момент публикации может остаться папка без записи журнала; это описано как ограничение. При обычном исключении обе стороны откатываются.
- Export changes включает семейство родителя целиком; это намеренно консервативный экспорт полных строк. Не меняйте в Tilda одновременно другие варианты этого семейства без свежего импорта в приложение.
- Неизменённые исходные аномалии отображаются предупреждениями. Новая критическая ошибка блокирует соответствующий сайт.
- Snapshot экспорта не становится baseline Tilda. Baseline обновляется только данными CSV.
- Подтверждение свежести человеком не считается доказательством. Сетевых запросов к Tilda приложение не делает.

Для будущего серверного хранилища слой домена и CSV независим. Следующий шаг — формальный протокол репозитория и перенос транзакционных запросов сервиса в его реализацию; авторизация и совместная работа намеренно отсутствуют в MVP.
